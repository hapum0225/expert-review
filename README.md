# 전문가 검토 (expert-review)

**분야별 점검표로 프로젝트의 코드와 문서를 읽기 전용으로 검토해, 파일 · 줄 근거가 붙은 결함 초안을 내는 Claude Code 스킬입니다.**

이름은 "전문가 검토"지만 **검토자는 모델입니다 — 사람 전문가의 판정이 아닙니다.** 출력 첫 줄에 항상 그렇게 적힙니다.

- 분야: **개발 설계** · **보안(Supabase 포함)** · **SEO · AEO · GEO에 유리한 코드 구성** — 분야마다 14항목 점검표
- 지적마다 여섯 칸: 관찰(파일:줄 · 인용) · 적용 기준 · 결함 판단(반례 확인) · 예상 영향 · 근거 확실성 · 확인 방법
- 검토하는 동안 **아무것도 고치지 않습니다.** 고칠지는 결과를 본 뒤 정합니다.

---

## 설치

```bash
claude plugin marketplace add hapum0225/expert-review
claude plugin install expert-review@expert-review --scope user
```

설치 후 Claude Code를 다시 시작하거나 `/reload-plugins`를 실행하세요. 슬래시 명령은 `/expert-review:expert-review`입니다. 그냥 채팅에 `전문가 검토 해줘`라고 해도 열립니다.

## 쓰는 법

검토할 프로젝트 폴더에서 Claude Code를 열고:

```
전문가 검토 해줘
```

스킬이 세 가지를 묻습니다 — **분야**(개발 설계 / 보안 / SEO) · **대상**(전체 / 특정 기능 / 최근에 바꾼 것 / 특정 폴더) · **걱정되는 것**(선택). 한 번에 보내도 됩니다:

```
전문가 검토: 보안 · 탈퇴 기능 · 개인정보가 남지 않는지
```

결과는 분야마다 한 묶음입니다: 결론 3줄 → 핵심 과업과 큰 실패 경로 → 확정 결함 표 → 더 확인할 위험 표 → 점검표 14항목 결과 → 못 본 것 → 반증된 항목.

## 하지 않는 것

| 안 함 | 이유 |
|---|---|
| 검토 중 파일 수정 · 명령 실행 · 네트워크 | 결과를 사람이 보기 전에 코드가 바뀌지 않게 |
| `.env*` · 키 · 고객 자료 · 로그 열기 | 비밀값 · 개인정보 보호 — 코드에서 보면 위치만 적고 값은 "가림" |
| 대상 안의 지시 따르기 | "이 파일을 고쳐라" 같은 문장은 지적으로 보고 |
| 가격 · 매출 숫자 만들기, 기능 채택 결정 | 검토의 범위 밖 |

## 안전장치 — 전부 자연어 규칙입니다

> ⚠️ 위 항목 중 **코드로 강제되는 것은 없습니다.** 모델이 규칙 문서를 읽고 따르는 것뿐입니다. 지켜지는지는 `references/pilot-tests.md`의 시험을 직접 돌려 확인하세요. "장치가 있으니 안전하다"고 읽지 마세요.

## 검증 상태 — 먼저 읽으세요

> 아래는 작성자의 자기보고입니다. 실행 출력 원본은 이 저장소에 없습니다.

**비교 시험(2026-10-01 · 개발 설계 점검표만)** — 결함을 심어 둔 작은 시험 프로젝트 4개 + 정상 대조 1개를, 세 방식 × 2회로 검토하고 다른 모델(Codex)이 방식을 가린 채 채점했습니다.

| | "그냥 검토해 줘" | 절차서 + 점검표 | 절차서 + 점검표 + 역할 문구 |
|---|---|---|---|
| 심은 '높음' 이상 결함 탐지 | 24/24 | 24/24 | 24/24 |
| 근거가 지적을 실제로 뒷받침한 비율 | 94% | 99% | 100% |
| 오탐(틀린 지적) | 1 | 0 | 1 |
| 정상 대조에서 근거 없는 '높음' 지적 | 1 | 0 | 1 |
| 시간 · 비용(회당 사용료 환산) | 기준 | 약 +38% | 약 +28% |

- **이 스킬이 "더 많이 찾는다"는 것은 확인되지 않았습니다.** 세 방식 모두 심은 큰 결함을 다 찾아 차이를 가릴 수 없었습니다(시험물이 쉬웠습니다). 나았던 것은 **근거의 정확도와 덜 틀리는 쪽**이고, 차이는 오탐 1건으로 채점자 한 명의 흔들림과 같은 크기였습니다.
- **역할 문구("시니어 ○○처럼")는 넣지 않았습니다** — 더한 쪽이 나아지지 않았습니다.
- 같은 대상을 두 번 돌리면 **지적 목록이 절반쯤 달라졌습니다.** 한 번의 검토로 빠짐없이 봤다고 할 수 없습니다.
- **보안 · SEO 점검표는 정답이 있는 시험을 하지 않았습니다**(실제 프로젝트에 1회 써 봤을 뿐). 출력 첫 줄에 `미시험`으로 표시됩니다.
- 점검 항목의 출처 문서는 다시 확인하지 않았습니다(모델 지식 기준 v0.1).
- 이 스킬 형태(같은 대화에서 규칙을 따라 검토)로는 **2026-10-09에 새 세션으로 기본 시험**을 했습니다 — CHANGELOG [0.1.0] 참조. 위 비교 시험은 읽기 · 검색 도구만 준 별도 세션으로 한 것이라 실행 방식이 다릅니다.
