# 렌즈: SEO · AEO · GEO에 유리한 코드 구성 (약자 E) v0.2

> 시험 상태: **정답 시험 없음** — 비공개 실제 프로젝트 1회 검토에서 출력 형식 · 안전 규칙이 지켜진 것만 확인했다(2026-10-15). 결과는 더 조심해서 읽는다.
> 근거: 2026-10-15 웹에서 열어 확인한 공식 자료 58건(Google 검색 센터 36 · Bing/IndexNow 5 · Next.js 11 · 기타) — 항목별 근거와 링크는 `lens-seo-sources.md`. Next.js 근거는 문서 표기 v16.4.0 기준 — 대상 프로젝트 버전이 다르면 동작이 다를 수 있다. **네이버 서치어드바이저 공식 원문은 열지 못했다**(E12는 방향성 그대로).
> 등급: 확립 = 공식 문서 · 표준 / 방향성 = 연구 · 관행 / 추정 = 근거가 약한 것.
> **마케팅 점검표와 겹치는 것은 여기서 보지 않는다**: 첫 화면 문구 · 행동 버튼(M1~M3) · FAQ 내용(M10) · 측정(M13) · 페이지 간 문구 일치(M14) · 모바일 첫 화면(M15). E4 · E7은 태그 · 기술 항목만 본다.
> **AI 검색(AEO · GEO)에 대해 공식이 말하는 것**: Google은 AI 개요 · AI 모드를 위한 **추가 요건이나 특별한 최적화가 없다**고 밝혔다 — 색인 · 스니펫 요건을 갖추는 일반 SEO가 곧 생성형 검색 대비다. llms.txt는 Google 검색에 쓰이지 않는다(2026-06-15 명시). FAQ 리치 결과는 2026-05-07부터 검색에 나오지 않는다. 검색어 변형마다 페이지를 대량으로 만드는 것은 스팸 정책 위반 소지다. "질문-답 블록이 AI 인용을 늘린다"는 주장은 공식 · 검증 근거를 찾지 못했다(추정).

| 항목 | 예/아니오로 물을 것 | 등급 |
|---|---|---|
| E1 색인 가능성 | ① robots(`robots.ts`)가 공개 페이지와 화면에 필요한 CSS · JS를 막지 않는가 ② 검색에 나오면 안 되는 곳(관리자 · 개인 화면)을 robots 차단만으로 숨기지 않고 `noindex`나 로그인으로 막는가 ③ 공개 페이지에 의도하지 않은 `noindex`가 없는가(Next.js는 페이지의 `robots`가 레이아웃 값을 통째로 대체) | 확립 |
| E2 사이트맵 | ① 사이트맵이 색인 대상 공개 주소만 절대 주소로 담는가 ② `lastModified`가 실제 수정 시각이고, 모든 주소에 `new Date()`를 일괄로 넣지 않았는가 ③ 사이트맵이 없다면 모든 공개 페이지가 내부 링크로 닿는가(약 500쪽 이하 · 내부 링크 충분하면 필수 아님) | 확립 |
| E3 렌더링 방식 | ① 공개 콘텐츠와 주요 링크가 서버가 만든 HTML에 들어 있는가(`'use client'` 화면에서 마운트 뒤 fetch로만 채워지지 않는가) ② title · description을 서버 컴포넌트(layout · page)에서 내보내는가 | 확립 |
| E4 메타데이터 | ① 공개 페이지마다 다른 title이 나오는가(`title.default` + `template` 또는 페이지별) ② 동적 경로는 `generateMetadata`로 데이터에 맞는 title · description을 내는가 ③ 같은 구간에서 `metadata`와 `generateMetadata`를 둘 다 내보내지 않았는가 | 확립(존재 · 고유성) |
| E5 표준 주소 | ① 공개 페이지가 `metadataBase` + `alternates.canonical`로 절대 주소 canonical을 내는가 ② 쿼리 · 정렬 · 추적 파라미터 변형이 본 주소를 canonical로 가리키는가 ③ http/https · www · 끝 슬래시 변형이 서버 리디렉션으로 한 가지에 모이는가(canonical은 힌트일 뿐 명령이 아님) | 확립 |
| E6 구조화 데이터 | ① 실제로 있는 유형(조직 · 행사 · 지역 사업장 등)만 JSON-LD로 넣었고 화면에 보이는 내용과 같은가 ② 그 유형의 필수 속성이 있는가(행사: name · startDate · location / 지역 사업장: name · address) ③ JSON-LD를 넣을 때 `<`를 이스케이프했는가. FAQPage는 리치 결과가 없어졌으므로 가점하지 않는다 | 확립(지원 유형에 한해) |
| E7 공유 미리보기 | ① `og:image`가 절대 주소로 나오는가 ② 페이지별로 달라야 할 곳에서 `openGraph` 전체를 다시 지정했는가(일부만 지정하면 레이아웃 값이 통째로 사라짐) ③ 대표 이미지가 로고 · 글자 이미지가 아닌가 | 확립(태그 형식) · 방향성(메신저 미리보기) |
| E8 문서 구조 | ① 의미 있는 이미지에 알맞은 `alt`가 있는가(장식은 빈 alt · 키워드 나열 아님) ② 제목이 h1부터 단계를 건너뛰지 않는가("h1 하나"는 공식 규칙이 아님) ③ `<html lang="ko">`가 있는가(접근성 요건 · Google은 언어 판단에 쓰지 않음) ④ 가능한 곳에 시맨틱 태그를 쓰는가 | 확립(① ③ 접근성) · 방향성(② ④) |
| E9 내부 링크 | ① 공개 페이지끼리 이동이 `<Link>` · `<a href>`인가(`onClick` + `router.push`만이 아닌가) ② 중요한 공개 페이지마다 다른 페이지에서 오는 링크가 있는가 ③ 링크 글자가 "여기" · "더보기"가 아닌 설명형인가 ④ 없는 주소로 가는 링크가 없는가 | 확립 |
| E10 성능 코드 패턴 | ① 이미지가 `next/image`(또는 폭 · 높이 지정)로 레이아웃 이동을 막는가 ② 글꼴을 `next/font`로 자체 호스팅하는가 ③ 서버 컴포넌트로 둘 큰 화면이 불필요하게 `'use client'`로 묶여 있지 않은가. LCP · INP · CLS 수치는 미실측 | 확립(지표 기준) · 방향성(코드 → 수치 연결) |
| E11 주소 설계 | ① 공개 주소가 읽을 수 있는 단어이고 내부 번호만 있는 주소가 아닌가 ② 세션 · 토큰 · 개인 식별 값이 주소에 없는가 ③ 단어 구분이 하이픈인가 ④ 내용이 같은데 주소만 늘리는 파라미터가 없는가 | 확립(Google 권장 · "가능하면") |
| E12 네이버 | ① robots가 네이버 검색 로봇(Yeti)을 막지 않는가 ② 소유 확인용 메타 태그나 확인 파일이 코드에 있는가 ③ 사이트맵 주소가 robots에 적혀 있는가(제출 여부는 코드로 못 봄 → 자료 부족) | 방향성(공식 원문 미열람) |
| E13 생성형 검색 | ① 생성형 검색용으로 따로 만든 것이 스팸 소지가 되지 않는가: 보이지 않는 텍스트 · 검색어 변형마다 대량 생성한 페이지 · 마크업과 본문 불일치 ② (참고 · 감점 없음) 요약 · 질문-답 구조가 있으면 위치만 적는다 | 확립(금지 부분) · 추정(구조의 효과) |
| E14 llms.txt | 유무만 적는다(가점 · 감점 없음) | 확립(Google 검색 영향 없음) · 추정(다른 AI 서비스) |
| E15 상태 코드 · 404 · 리디렉션 | ① 없는 동적 경로가 `notFound()`로 404를 내는가(Next.js는 스트리밍이 시작된 뒤면 200으로 남음) ② 삭제 · 이전된 주소가 서버 리디렉션으로 처리되는가(JS · meta refresh 아님) ③ 오류 화면이 200 상태로 나가지 않는가 | 확립 |
| E16 목록 페이지 | 페이지 번호 · 필터가 있는 목록이라면 ① 페이지마다 고유 주소가 있는가 ② 다음 페이지 링크가 `<a href>`인가 ③ 첫 페이지를 모든 쪽의 canonical로 쓰지 않는가. 없으면 해당 없음 | 확립 |
| E17 이미지 색인 | ① 검색에 나와야 할 이미지가 `<img>`(또는 `next/image`)인가, CSS 배경이 아닌가 ② 파일 이름이 짧고 내용을 설명하는가 | 확립 |
| E18 다국어 · hreflang | 한국어 한 가지면 해당 없음. 언어 · 지역 버전이 있다면 ① 버전마다 별도 주소 ② 서로 가리키는가 ③ x-default가 있는가 | 확립(조건부) |

이 렌즈가 판단하지 못하는 것: 실제 순위 · 유입 · 색인 상태와 Search Console · 서치어드바이저 등록 · 제출 상태, 실제 렌더 결과와 상태 코드(런타임), 배포 설정(실제 `/robots.txt` · 헤더 · 리디렉션), 성능 수치(필드 데이터), 콘텐츠 품질과 검색 의도 적합성, AI 검색에서의 실제 인용(공식이 별도 요건 없다고 하므로 통과가 인용을 예측하지 못함), 외부 링크 · 평판, 네이버 고유 동작(공식 원문 미열람).
