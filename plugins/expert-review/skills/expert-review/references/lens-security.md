# 렌즈: 보안 — Supabase 포함 (약자 S) v0.1

> 시험 상태: **미시험** — 실제 프로젝트에 1회 써 봤을 뿐, 정답이 있는 시험물로 재 보지 않았다.

점검 항목의 출처 문서는 다시 확인하지 않았다(모델 지식 기준). 등급: 확립 = 공식 문서·표준이 있는 것 / 방향성 = 관행·연구 / 추정 = 근거가 약한 것.

| 항목 | 예/아니오로 물을 것 | 등급 |
|---|---|---|
| S1 행 수준 보안(RLS) | 공개 스키마의 모든 테이블에 RLS가 켜져 있는가(꺼진 테이블 목록) | 확립 |
| S2 정책 내용 | 정책이 본인 · 역할로 제한하는가. `using (true)` 같은 넓은 정책, insert/update의 `with check` 누락 | 확립 |
| S3 서비스 키 | service_role 키가 브라우저로 가는 코드 · `NEXT_PUBLIC_` 변수 · 클라이언트 묶음에 닿지 않는가(값은 보지 않는다) | 확립 |
| S4 서버 쪽 권한 확인 | 서버 액션 · API 경로 · RPC가 호출자 신원과 권한을 서버에서 확인하는가. 클라이언트가 보낸 사용자 ID를 믿지 않는가 | 확립 |
| S5 SECURITY DEFINER 함수 | `search_path` 고정, 함수 안의 권한 확인, anon/authenticated에 준 실행 권한 | 확립 |
| S6 관리자 기능 | 관리자 판정이 서버 · DB에서 이뤄지는가(화면 경로만 숨긴 것은 아닌가) | 확립 |
| S7 입력 검증 · 주입 | 문자열을 이어 붙인 SQL · 필터, 동적 정렬 · 컬럼명, 검증 없는 HTML 삽입 | 확립 |
| S8 인증 흐름 | 로그인 뒤 이동 주소 검증, 세션 쿠키 처리, 소셜 · 이메일 로그인 콜백 | 확립 |
| S9 파일 저장소 | 버킷 공개 여부와 정책, 올리는 파일의 형식 · 크기 제한 | 확립 |
| S10 개인정보 노출 | 응답 · 페이지 데이터에 필요 이상의 개인정보가 실리지 않는가. 다른 사용자의 데이터를 조회할 수 있는가 | 확립 |
| S11 비밀값 관리 | 저장소에 커밋된 키 · 토큰 · 비밀번호(위치만), `.gitignore` | 확립 |
| S12 남용 방어 | 가입 · 로그인 · 신청 · 메시지 경로의 반복 호출 방어 | 방향성 |
| S13 외부 호출 경로 | 예약 작업 · 웹훅처럼 밖에서 부르는 경로의 인증 | 확립 |
| S14 의존성 | 알려진 취약 버전 여부 — 이 검토로는 확인할 수 없으므로 "미실측"으로 둔다 | — |

이 렌즈가 판단하지 못하는 것: **운영 DB의 실제 정책 상태**(마이그레이션 · SQL 파일 기준으로만 본다 — 파일과 운영이 다를 수 있음), 침투 시험 결과, 의존성 취약점.
