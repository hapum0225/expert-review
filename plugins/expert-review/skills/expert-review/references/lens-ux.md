# 렌즈: UX/UI (약자 X) v0.2

> 시험 상태: 2026-11-09 신설 · 2026-11-11 일반화(v0.2) · **정답 시험 없음**. v0.2는 비공개 실제 프로젝트 1회 검토에서 출력 형식과 안전 감사(파일 변경 0 · 읽기 범위 위반 0)를 확인했다. 이전 v0.1의 실제 적용 2회 중 1회에는 읽기 범위 감사 위반 2건(절차가 시킨 `.git` 읽기)이 있었다 — 안전 규칙 준수를 판본 전체로 확인했다고 할 수 없다. 결과는 더 조심해서 읽는다.
> 근거: Don Norman · NN/g 10원칙 · 시각 디자인 원칙 + 표준(WCAG 2.2) · 공식 플랫폼 지침(Apple HIG · Material) + 공개 자료 2건(unslop — X21 · Hallmark — X22, 각각 한 곳에서 나온 자료라 출처 규칙상 추정). 항목별 출처와 등급 근거 · 저작자 표시는 `lens-ux-sources.md`. WCAG 2.2와 NN/g 10원칙은 2026-11-11 페이지를 열어 번호 · 제목 · 등급을 대조했다. Apple HIG · Material 수치는 아직 원문 미확인.
> 등급: 확립 = 표준 · 공식 지침 / 방향성 = 연구 · 널리 쓰이는 원칙(Nielsen · Norman) / 추정 = 근거가 약하거나 원문 미확인. **출처 규칙(2026-10-22)**: 공식 문서 · 표준이 아닌 한 출처(한 사람 · 한 영상 · 한 글)뿐인 기준은 '추정'으로 두고 판정 근거로 쓰지 않으며, 출처끼리 엇갈리면 합치지 않고 나란히 적는다.

**보는 대상**: 화면 시안(HTML · 이미지 설명) · 화면 컴포넌트 코드(예: React · Next.js라면 `*.tsx` · `components/**` · 스타일 파일 `*.css`) · 화면 문구 · 디자인 브리프(계획서의 위계 · 액션 · 상태 · 비노출 칸).
**대상 프로젝트 규칙 먼저**: 대상 폴더에 말투 · 화면 비노출 · 디자인 규칙 문서(CLAUDE.md · AGENTS.md · 디자인 가이드 등)가 있으면 먼저 찾아 X18 · X19의 기준으로 쓰고, 지적에 그 문서 위치를 적는다. 없으면 X18 · X19에 '프로젝트 규칙 없음 — 일반 기준으로 봄'이라 적는다. 대상 프로젝트에서 확인되지 않은 자체 기준은 확정 결함의 근거로 쓰지 않는다.
**마케팅 점검표와 겹치는 것은 여기서 보지 않는다**: 첫 화면 가치 제안(M1) · CTA 문구의 설득력(M3) · 폼 칸 수(M4) · 신뢰 요소(M6) · 가격 표시(M9) · 개인정보 고지(M11) · 수신 동의(M12).
**개발 · 보안 점검표와 겹치는 것도 보지 않는다**: 권한 판정 위치(D·S) · PII 반환 여부의 서버 측(S). 여기서는 **화면에 그려지는 것**만 본다 — 같은 값이 서버에서 막혔는지는 보안 렌즈 몫.
**먼저 정할 것**: 화면의 유형(목록 · 상세 · 입력 · 관리)과 그 화면에서 사용자가 해야 할 단 하나의 행동. 브리프에 적혀 있으면 그것을 쓰고, 없으면 코드 · 시안에서 추정해 "추정"이라 적는다.

이 렌즈가 판단하지 못하는 것: 실제 사용자의 이해도 · 과업 완료율(사용성 시험 필요) · 미적 취향 · 브랜드 적합성 · 실제 기기의 렌더링(파일만 읽는다 — 시안이 "재현"이면 재현으로 본다) · 색상 토큰 값 자체의 적절성(디자인 시스템 정본 몫).

## 지적을 적는 법 (이 렌즈 전용 보충)
- 시안(HTML)을 볼 때는 **코드의 CSS 값**(글자 크기 · 간격 · 들여쓰기 · 선)을 인용해 판정한다 — "보기에 좁다"가 아니라 "`.row` 간격 9px · `.group .inner` 들여쓰기 10px"처럼.
